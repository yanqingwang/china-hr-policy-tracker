# 输出格式标准（强制）

> 本文件为仓库**唯一输出格式规范**。任何数据更新（新增城市、年度刷新、脚本抓取）
> 都必须产出符合本规范的 `reports/社保公积金政策.md`。

## 1. 文件与产物

| 产物 | 路径 | 说明 |
|---|---|---|
| 主表 | `reports/社保公积金政策.md` | 每次更新覆盖 |
| 日期快照 | `reports/社保公积金政策_YYYY-MM-DD.md` | 每次更新新增，不覆盖 |
| 数据快照 | `data/city_insurance_2026_YYYY-MM-DD.json` | 与主表同源 |

## 2. 标题与前言（固定）

```markdown
# 📋 社保公积金政策总表（2026 年度）

**生成日期：YYYY-MM-DD**

> 数据来源：AI 多模型核实（...）+ doubao-seed-evolving 终审裁决 + 脚本抓取严格增量更新。
> **校验方式列**：AI核实=三模型交叉+豆包终审；脚本更新=2026发布+数值合理性过滤后的增量；待核=暂未获取官方值。
> **更新频率列**：社保/公积金缴费基数通常**年度**调整（4月/7月为高峰）；失业费率阶段性延续；工伤行业浮动不定期。
> 生效日期若无记录暂时留空；数据以各市人社局/医保局/公积金中心官方通告为准。

---

## 📊 覆盖：N 城 × 7 险种
```

## 3. 表头（固定 9 列）

```markdown
| 城市 | 生效日期 | 险种 | 基数上限(元) | 基数下限(元) | 个人% | 公司% | 校验方式 | 更新频率 |
|---|---|---|---|---|---|---|---|---|
```

**这是长表（long format）**：每个城市 × 每个险种占一行。
**不是**每城市一个小 markdown 表的宽表格式。

## 4. 排序

- 城市：字典序升序
- 城市内险种：`养老 → 医疗 → 生育 → 失业 → 工伤 → 公积金 → 补充公积金`

## 5. 行省略规则（`src/insurance_rules.py`）

不输出该行，当：
1. 该险种为 `None`（城市无此险种，如多数城市无补充公积金）
2. 个人比例 = 0 **且** 公司比例为 `0 / 0.0 / 并入医保 / 无 / —`

## 6. 列取值

| 列 | 规则 |
|---|---|
| 生效日期 | 无记录写 `—` |
| 基数上限/下限 | 缺失写 `—`，**不写 null/None** |
| 个人% / 公司% | 缺失写 `—` |
| 校验方式 | `AI核实(YYYY-MM-DD)·glm/kimi/deepseek三模型一致·豆包终审` / `脚本更新(日期)·严格增量` / `待核(暂未获取官方值,日期)` |
| 更新频率 | 养老/医疗/生育/公积金/补充公积金=`年度`；失业=`年度(阶段性费率延续)`；工伤=`不定期(行业浮动)` |

## 7. 校验与溯源要求

- 数据源优先级：**gov.cn 官方原文 > 双模型独立抽取 > 豆包仲裁**
- 官方原文未提及的字段一律置 `null`，**禁止臆断**
- 校验流程：`GLM-5.3-Flash` 与 `Qwen-Flash` 各自独立从同一批官方原文抽取 → 字段级比对 → 分歧交 `Doubao-Seed-Evolving` 依据原文终审
- 省级统筹：养老基数全省统一（吉林为特例），同省各市标注 `_省级统筹` 溯源；公积金按市级独立确定，**不聚合**
- 存疑数据必须在该城市对应行的校验方式列写明「存疑/待核实」及原因

## 8. 生成命令

```bash
# 仓库内
python3 scripts/gen_insurance_report.py --dated
# 服务器
/www/hr-policy-tracker/venv/bin/python /www/hr-policy-tracker/scripts/gen_insurance_report.py --dated
```

注意：服务器系统 python 为旧版（不支持 `list[dict]` 语法），必须用 venv 内的 python。
